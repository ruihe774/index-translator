# CLAUDE.md

Local translation app. One Bun process serves the REST/SSE API and the static web app, and runs three engines
in-process through `bun:ffi`, each on its own worker thread: llama.cpp (libllama, Vulkan; one model at a time; the
chat model also translates images through libmtmd), audio.cpp (IndexTTS-2.5 reading aloud, plus Mel-Band RoFormer voice
separation, plus a preview of transcription: CED, Silero VAD and MOSS-Transcribe-Diarize) and ONNX Runtime on CPU (`POST /segment`: SaT sentence ends; `POST /align`: LaBSE embeddings and AIlign's
DP). `POST /webpage` opens a page in a headless browser (`Bun.WebView`) and answers Markdown. User docs: README.md.
On Windows read `WINDOWS.md` first.

## Commands

Use Bun canary (`bun --revision` must end in `-canary…`; `lint:ts` needs its builtins). Cloud session without it: `curl -fsSL -o /tmp/bun.zip https://github.com/oven-sh/bun/releases/download/canary/bun-linux-x64.zip && unzip -qo /tmp/bun.zip -d /tmp/bun && install -m755 /tmp/bun/bun-linux-x64/bun ~/.bun/bin/bun`.

Run `bun install` before `lint:*` or `e2e` when `node_modules` is missing or stale.

- Run: `bun src/server.ts` (`--help` lists every setting). Dev: `bun run dev` (also `ALLOWED_WEBPAGE_DOMAINS='*'`)
- Test: `bun test` (mock engine, no GPU). E2E/a11y: `bun run e2e` (Playwright, mock engine; `e2e/README.md`; `bunx playwright install chromium` or `CHROMIUM_PATH`)
- Page load times on a throttled link, with and without the service worker, over HTTP/1.1 and HTTP/2: `bun run e2e:perf` (`e2e/README.md`; not a test, asserts nothing)
- Coverage: `bun run test:coverage`, `bun run e2e:coverage` (`e2e/coverage.ts`); workers are not measured
- Lint and typecheck: `bun run lint:ts` (`bun lint`: builtin linter and type checker, no `tsc`; each file uses its nearest `tsconfig.json`; config under `[lint]` in `bunfig.toml`). Errors and warnings stay at zero. Suppress with `// eslint-disable-next-line <rule> -- <why>` (a `: <why>` suffix suppresses nothing). **If a change introduces lint errors or warnings, tell the user which rules failed, even if you then fix them** (the user audits the rules).
- JS browser support: `bun run lint:es` (ESLint with `eslint-plugin-browser-compat` against `.browserslistrc` and `eslint-plugin-es-x` up to `ES_EDITION` in `scripts/lint_es.ts`). It lints what `public/*.ts` becomes under `Bun.Transpiler`: `bun:*` and `*.json` imports are errors. Bun strips comments, so `eslint-disable` in `public/` does nothing: an exception goes in `scripts/lint_es.ts` (`settings.polyfills` or a rule override) with a comment why. Same reporting rule as `lint:ts`
- Format: `bun run format:write` / `format:check` (120 columns; Markdown is hand-formatted)
- CSS: `bun run lint:css`. Markdown conformance: `bun scripts/commonmark.ts`. Long documents: `MODEL=index-nailong-9b bun scripts/longtext.ts http://127.0.0.1:3000`. Long subtitles (the essays cut into cues, in the page's chunks and requests; `MAX_CUES=…`, `CHUNK=…`, `OVERLAP=…`): `bun scripts/longsubs.ts http://127.0.0.1:3000 [out-dir]`
- No `check`, `lint` or `format` script in `package.json` on purpose: each would shadow the builtin.

Setup (Linux and Windows):
- `bun scripts/build_llama.ts`: libllama, libmtmd, Vulkan, one CPU backend (AVX2 on x86-64, Armv8.2-A+dotprod+fp16 on aarch64, unless `--native`), `libllama-shim.so` into `vendor/llama.cpp` (`--shim` only recompiles `src/llama-shim.c` and `src/llama-shim-ext.cpp`; a build from before MTP lacks `include/llama-ext.h` and needs the full build)
- `bun scripts/build_audiocpp.ts`: `vendor/audio.cpp/libaudiocpp.so` from the pinned commit (a commit on main, not a release, for transcription, plus a Vulkan Flash Attention change for RoFormer from `ruihe774/audio.cpp` until upstream merges it) plus `scripts/patches/audiocpp-abort.patch` and `audiocpp-custom-output.patch`, in that order (AVX2 unless `--native`), and Silero VAD's weights and license beside it
- `bun scripts/build_soxr.ts`: `vendor/soxr/libsoxr.so.0` (`soxr.dll`); required, opened before libaudiocpp (see Invariants)
- `bun scripts/build_libopus.ts`: `vendor/opus/libopus.so.0` (`opus.dll`), libopus 1.6.1 from the pinned commit, runtime SIMD dispatch, no DNN parts; the speech stream's Opus encoder (without it speech is WAV) and the decoder of Ogg Opus uploads (without it uploads are WAV only), which `test/opus-stream.test.ts` also reads the stream back with
- `bun scripts/fetch_models.ts`: models (about 19.2 GiB) and example voices; `--model <id>`, `HF_ENDPOINT`. Includes `sat-3l-sm` (`POST /segment`), `labse` (`POST /align`) and `moss-transcribe-diarize` (`POST /transcriptions`)
- `bun scripts/fetch_onnxruntime.ts`, `fetch_web_libs.ts` (PDF, undoc), `fetch_turndown.ts`: each fills a `vendor/` or `public/vendor/` directory (not in git, pinned by checksum); `POST /segment`, `/webpage`, PDF and Word are unavailable or their tests skipped without them, and packaging requires all of them
- `bun scripts/build_appimage.ts`, `bun scripts/build_installer.ts` (need both engines built; `WINDOWS.md`)
- CUDA variant (Linux x86-64 and aarch64, AppImage only): `build_llama.ts --cuda`, `build_audiocpp.ts --cuda`, `build_appimage.ts --cuda` (CUDA 13 toolkit via `CUDA_PATH` or `/usr/local/cuda-13`; `--cuda-arch=native` for a quick local build). One GPU backend per variant, never both: CUDA builds have no Vulkan (`vendor/llama.cpp-cuda`, `vendor/audio.cpp-cuda`, run with `LLAMA_DIR`, `AUDIO_DIR`, `SPEECH_BACKEND=cuda`), Vulkan builds no CUDA; `build_appimage.ts` refuses a mixed pair. The CUDA runtime libraries (cudart, cuBLAS) sit beside each engine library (`$ORIGIN` run path), not the driver's `libcuda.so.1`; the AppImage `Index_Translator-<arch>-cuda.AppImage` gets `SPEECH_BACKEND=cuda` from `AppRun`, and `preflight` names the NVIDIA driver when `libggml-cuda.so` is there. CI: job `appimage-cuda` (manual runs only, `workflow_dispatch`; toolkit from NVIDIA's apt repository, `CUDA_PACKAGE_VERSION`)

No npm runtime dependencies; no build step for the web app.

## Layout

- `src/`: `server.ts` entry; `app.ts` the route table; its parts: `parse.ts` (request bodies), `http.ts` (`ApiError`, error mapping, JSON), `translate.ts` (prompt budget, generation as events), `jobs.ts` (streamed jobs of translations and transcriptions, resume), `tickets.ts` (an engine's waiting line), `health.ts`, `speech-response.ts` (WAV or Opus); `config.ts`; `static.ts` (`.ts` in `public/` transpiled on request); `queue.ts`; `preflight.ts` + `llama-probe.ts`; `models.ts`; `prompt.ts` (NativeLong templates); `image.ts`
- Engine pairs, server + worker: `llama.ts` / `llama-worker.ts` (`llama-ffi.ts` bindings, `llama-shim.c` struct calls and the MTP drafter, `llama-shim-ext.cpp` C names for `llama-ext.h`); `speech.ts` / `speech-worker.ts` (`audiocpp-ffi.ts`, no C shim; `transcript.ts` the engine-free parts of a transcription); `segment.ts` / `segment-worker.ts` (`onnxruntime-ffi.ts`, `sat.ts`, `labse.ts`, `align.ts`; none of the last three touch the runtime); `cpu.ts` thread counts; `opus-stream.ts` (`opus-ffi.ts`), `opus-file.ts` (Ogg Opus uploads), `resample.ts`, `accept.ts`, `wav.ts`; `public/ogg-opus.ts` (Ogg muxer and demuxer, shared with the page: no Bun, no DOM; listed in the root `tsconfig.json`; `src/` imports it as `../public/ogg-opus`)
- `webpage.ts` (`POST /webpage` through `Bun.WebView`) + `page/extract.ts`, which runs inside the fetched page (own `tsconfig.json` with the DOM; read as text, types stripped, sent after turndown; a script, no imports)
- `public/`: web app. `state.ts` + `render.ts` hold the state behind the always-shown controls and the one synchronous `render()` (callers move focus right after `setState`); `elements/` light-DOM custom elements enhancing `index.html`; `css/` one file per feature, `style.css` only the layer order and `@import`s
- `e2e/mock-server.ts`: real app on the `test/helpers/mock-engine.ts` mocks, scriptable via a control port. Fixtures in `test/fixtures/` (`sample.pdf`: `uv run make_sample_pdf.py`; `sample.docx`: `make_sample_docx.py`; `media/`: `bun test/fixtures/make_media.ts`, ffmpeg and mkvmerge (a rerun rewrites every file with other bytes: keep the ones a change does not need); `test/helpers/ebml.ts` writes the Matroska edge cases by hand)

## Invariants

- The backend never picks a model from the text; the client does (`public/select-model.ts`). `LONG_THRESHOLD_LETTERS = 11_000` there is the switch point (the chat model loses paragraphs beyond about 11–16K letters); keep docs in sync.
- A model swap frees the loaded model and loads the other; repeated requests do not reload.
- libllama is only called from its worker thread, and every call blocks it. Threads: `LLAMA_THREADS`, else `inferenceThreads` (`src/cpu.ts`): `min(performance cores, navigator.hardwareConcurrency, 8)` (ggml waits for its slowest thread, so E-cores slow the P-cores down). `SEGMENT_THREADS` has the same default; nothing shares out the cores between the two. A generation returns to the worker's event loop after each decode, which is when `/tokenize` and cancellations are handled.
- **QoS on Windows** (`src/qos.ts`): Windows infers QoS from a process's windows, and the server has none, so its threads may be put on E-cores. `GET /health?visible=true` from a loopback address (`server.requestIP`; a local reverse proxy counts as loopback) renews a lease of `QOS_LEASE_MS` (15 s, three polls) during which the whole process opts out of execution-speed throttling (`SetProcessInformation(ProcessPowerThrottling)`, control mask set, state mask clear: HighQoS); when it ends, or at `stop()`, both masks are cleared and Windows decides again. The page sends it with every poll, and polls only while `document.hidden` is false (a fully covered window counts as hidden in Chromium). No lease is per client and `visible=false` releases nothing (another tab may be shown). A refused call is logged once and not tried again. `startApp`'s sixth argument is the setter (tests pass a recorder); elsewhere than Windows it is undefined and nothing happens.
- **Multi-token prediction** (MTP; `Model.next`, `shim_mtp_*` in `src/llama-shim.c`): for a `ModelSpec` with `mtp` (the chat model; NativeLong not yet), `MTP` not `0`, `GPU_LAYERS` all and `MTP_MIN_GPU_BYTES` (15.5 GiB, so a 16 GiB card, which reports about 15.9, qualifies: MTP adds about 0.65 GiB at `CTX_SIZE` 65536; on an RX 9070 the chat model, an image and reading aloud still load with it, reading aloud taking the VRAM left, and text decodes about 1.4× as fast) of total GPU memory, decided at load. The model's MTP layer drafts `MTP_DRAFT` (2) tokens in a context of type MTP; one decode of the target checks them; greedy matching keeps the target's own choices, and `llama_memory_seq_rm` drops the rest from both contexts (the target is created with `n_rs_seq = MTP_DRAFT` so its recurrent layers can roll back). The MTP layer reads the target's hidden state per token (`llama_get_embeddings_nextn`, staging API from `llama-ext.h`, C names from `llama-shim-ext.cpp`), so every text decode is followed by `shim_mtp_catch_up`. Ported from llama.cpp's `common/speculative.cpp` (draft-mtp) and the server's verification. Text prompts only: after an image the worker decodes one token at a time. Output can differ from token-at-a-time decoding at near-ties (batched verification computes in a different order), never by a confident choice; check with a teacher-forced comparison after changing it.
- The prompt is written by `chatPrompt` (`src/llama-ffi.ts`), not the Jinja template: ChatML, token-identical to the template with `enable_thinking=false`. A non-ChatML template fails to load.
- **Image input** (`image` on `POST /translate`, chat model only):
  - Every upload is decoded by `Bun.Image` and re-encoded as an uncompressed PNG (`prepareImage`, before the queue); JPEG, PNG, WebP only, 8 MiB, 50 million pixels. It is resized once to the size libmtmd would pick (`engineSize`), so libmtmd copies it without resampling.
  - The shim decodes with libmtmd's own `stbi_load_from_memory` (exported without a header), not `mtmd_helper_bitmap_init_from_buf`, which drops alpha: transparency becomes white (dark text would otherwise be black on black).
  - The prompt is `buildImagePrompt`, then the image: `imageChatPrompt` splits `chatPrompt` there and `mtmd_tokenize_from_parts` puts the image between `<|vision_start|>` and `<|vision_end|>`. No media marker, so one in the text is text.
  - M-RoPE: an image takes `max(rows, columns)` positions, not its token count. After an image prompt the worker decodes with explicit positions (`shim_decode_at`, `Model.nextPos`); `llama_batch_get_one` would continue one past the image's first position.
  - The mmproj GGUF (`ModelSpec.mmproj`) is loaded by the first image and freed with the model. Missing: `503 image_unavailable`, checked per request.
  - Counting an image's tokens means preparing it, so it goes through the worker's chain and `/tokenize` refuses images.
- Generation is greedy from an empty context. One at a time; up to `MAX_QUEUE` wait FIFO, beyond that `429 queue_full`. Closing the client connection cancels it, except for an SSE request with `resumable: true`: that job (`Job` in `src/jobs.ts`) runs on for `RESUME_GRACE_MS` with no reader, can be read again by `GET /translations/{id}/events` (`Last-Event-ID`) and is cancelled by `DELETE /translations/{id}`; finished ones are kept 10 minutes.
- `MAX_INPUT_TOKENS + 64 < CTX_SIZE`, else startup fails. Output is capped at 4 × prompt tokens + 512 unless `max_output_tokens` is set.
- No authentication: keep `HOST` on loopback or behind a proxy; `ALLOWED_ORIGINS` / `ALLOWED_HOSTS` control access.
- `src/server.ts` runs `preflight` first and exits 1 with one message when the machine cannot run the translator: libraries do not open (checked in a separate process), no CPU backend, no Vulkan GPU while `GPU_LAYERS` is not `0` (CPU-type devices such as lavapipe do not count), or the default model's file is missing. `startApp` does not check; tests and e2e use the mocks.
- The engines (llama.cpp, audio.cpp, ONNX Runtime) share the process: a crash in any takes the server down.
- **Sentence segmentation** (`src/segment.ts`): ONNX Runtime is only called from the segmentation worker, started by the first `POST /segment` or `POST /align` (never at startup); freed after `SEGMENT_IDLE_UNLOAD` seconds idle; a failed load is retried. `onnxruntime-ffi.ts` reads function pointers from `OrtApi` by slot, no C shim; strings and arrays the library keeps pointers to must stay referenced from JS. `sat.ts` is wtpsplit's SaT with tokens identical to Hugging Face's XLM-R tokenizer. Offsets are UTF-16 units of the text as sent. Own single-slot queue, like speech.
- **Sentence alignment** (`POST /align`, `src/align.ts`, `src/labse.ts`): LaBSE is the segmentation worker's second ONNX session, same queue, own load state (`ModelSlot`) and idle unload; `ALIGN=0` turns it off. The quantized model ends at `last_hidden_state`, so the embedding is ours: [CLS] through sentence-transformers' Dense (768 → 768, tanh), L2-normalized; the BERT WordPiece tokenizer must stay identical to Hugging Face's (`test/labse-native.test.ts`). `align.ts` is the DP step of the AIlign paper (arXiv:2403.11921, CC BY 4.0) written from the paper, never from its CC BY-NC code. `unit: "paragraphs"` embeds each paragraph by its opening and measures length by what it translates (`translatedLengths`); an empty side costs 0.7 (at 1 a dropped paragraph joins a neighbour, often the wrong one); no 2-2 group. The constants were tuned against dropped/merged/split blocks in real translations; retune with such a test, not by eye. Known limit: a short block left out is often matched as merged into its neighbour.
- libaudiocpp is only called from the speech worker, started by the first `POST /speech` (never at startup); freed after `SPEECH_IDLE_UNLOAD` seconds idle. A failed load is retried by the next request.
- libaudiocpp must link its ggml statically and export only `audiocpp_*`. audio.cpp's ggml is a fork with the same SONAME `libggml.so.0` as llama.cpp's; shared ggml binds to the loaded libllama and dies with an undefined symbol.
- libsoxr: audio.cpp `dlopen`s `libsoxr.so.0` / `soxr.dll` by bare name and otherwise falls back to a resampler that sounds different. So `openSoxr` (`src/audiocpp-ffi.ts`) opens our `vendor/soxr` build by full path before libaudiocpp; the loader hands an already-loaded library to a later request for its name. A missing build is an error, not a fallback. Changing the audio.cpp pin: recheck the lookup names and the `soxr_*` symbols.
- Aborting an utterance: audio.cpp has no abort, so our patch adds `audiocpp_set_abort_flag` (checked before every decoding step, diffusion step and the vocoder). Each `synthesize` message carries its own 4-byte `SharedArrayBuffer`, set on client abort; the worker answers `aborted`. The request is answered at once but keeps its queue slot until that answer. Not stoppable: conditioning before the first step, a model load, a separation.
- Uploaded voice samples are separated by Mel-Band RoFormer (`POST /voices` → worker `separate`) when a `.gguf` is in `SEPARATION_MODEL_DIR`; otherwise kept as uploaded. Speech and separation models are never loaded together (`separating` is the gate). Failure is `SeparationError` (`502 speech_error`), never a fallback to the unseparated sample.
- Speech has its own single-slot queue and never holds the translation queue; both may use the GPU at once.
- **Transcription** (`POST /transcriptions`, a preview; `speech.transcribe`, worker `transcribe`): on the speech worker and in the speech queue; it frees the speech model and holds the same GPU gate as a separation (`alone` in `speech.ts`), so reading aloud waits for it. Needs the engine and MOSS, not IndexTTS (`TRANSCRIBE`, not `SPEECH`). Pipeline in the worker: separation when asked (`separate=auto|true|false`; `auto` = the model is installed, and only the stretches where CED-tiny, on the CPU, hears Music ≥ 0.3 in a 10 s window (one every 5 s, all of the recording: about 8 s for 30 minutes; speech-only recordings scored ≤ 0.16, music under talk 0.6–0.8) are separated, padded 2 s and joined across gaps under 8 s (`musicRegions`); each stretch with 2 s of context on both sides and RoFormer's `num_overlap` 1 (`TRANSCRIBE_SEPARATION_OVERLAP`, a session option: half the time of the model's 2, about 30× real time on an RX 9070, vocals at 32 dB SNR against 2; voice samples keep 2), written over the 16 kHz mono with a 0.5 s fade (`splice`), so times do not move, and the abort flag is checked between stretches; `true`, or `auto` without CED's file: the whole recording as one stretch; resampled to 44.1 kHz with libsoxr), mono at 16 kHz, `normalizeLoudness(…, true)` (gate 40 dB under the peak: the fixed -40 dBFS gate left very quiet recordings unchanged), Silero VAD on the CPU, then a cut to the speech only when more than `TRIM_SILENCE_SHARE` (30%) is silence (cutting a meeting with little silence raised its DER from 28.8% to 34.6%), then MOSS in a *streaming* session. Its text is read piece by piece (`SegmentReader`), each complete segment is posted with its times mapped back (`toOriginal`), and the abort flag is checked between pieces; the prefill and a stretch being separated are not stoppable. MOSS fails the run with "reached max_tokens" at its budget and loses the text; read as it is written, what came before stands (`truncated`). `maxTokens` is VRAM: audio.cpp reserves the cache for the prompt (12.5 tokens a second) plus the budget; 30 minutes with 20,000 took 15.9 of 16 GiB beside the chat model. MOSS repeats itself on music: `LoopGuard` stops it (six identical segments, or one starting past the end), and so does a segment still open after 1,000 characters (`SegmentReader.runaway`: a drawn-out 「ひーー」 ran to the token budget); stopped before any segment (a song without separation: MOSS writes only times and speaker tags), the run is a `speech_error`, not an empty `done`.
- **Transcription jobs** (`TRANSCRIPTION_JOBS` in `jobs.ts`): always resumable and never cancelled for lack of a reader (a phone may stay locked for the whole run); kept 30 minutes after they end, at most 16; `DELETE` cancels and forgets (a reader still gets `cancelled`). The body is a WAV or an Ogg Opus file (see Uploads in Ogg Opus) of at most `MAX_TRANSCRIBE_BYTES` (160 MiB), checked from its header before it is queued (`validateRecording`, `readRecordingInfo`), then kept in an anonymous file (a full line of waiting uploads in memory would be gigabytes) that the worker reads by descriptor and the job closes when it ends however it ends (also on a 429). Translation jobs keep their 2-minute grace and 10-minute keep.
- **Uploads in Ogg Opus** (`src/opus-file.ts`): `POST /voices` and `POST /transcriptions` take `audio/wav` and, when libopus is installed, `audio/ogg` (`uploadTypes`, listed as `upload_types` in `GET /voices` and `/health` `transcribe`; the declared type picks the parser, so an Ogg file sent as WAV is a 400). `demuxOggOpus` (`public/ogg-opus.ts`) reads a subset of Ogg: one logical stream (no chaining or multiplexing), family 0 (mono or stereo), from granule 0; it checks every page's CRC and sequence and that the last granule fits the packets' TOC durations, so the length is known and bounded before anything is decoded (8 MiB of tiny packets could otherwise claim hours). Decoded at 48 kHz, pre-skip dropped, cut at the last granule, output gain applied. A voice sample is decoded on the main thread, resampled to 44.1 kHz with libsoxr and kept as a 16-bit WAV (`opusSampleToWav`), so the rest of the voice path only knows WAV; a recording to transcribe is decoded by the worker (`readRecording`, told apart by its first bytes).
- **Uploads on disk** (`src/anonymous-file.ts`): voice samples and recordings to transcribe are written to a file in the first of `TMPDIR` (if set), `/var/tmp` (on disk; `/tmp` is often a tmpfs, so RAM) and `os.tmpdir()` where creating and writing it works (a missing, read-only or full directory is passed over), and unlinked at once; only the descriptor reaches it (the worker reads it by `fd`, which is the process's), and the system frees it on `close()` or when the process ends, a crash included, so nothing is left behind. On Windows the same code works because Bun opens with `FILE_SHARE_DELETE` and unlinks with POSIX semantics (NTFS, ReFS); `/var/tmp` is skipped there.
- Request bodies are read with `readBody` (`parse.ts`), which stops at the route's limit: `MAX_REQUEST_BYTES` is the largest route's (a transcription) and a chunked body declares no length.
- **Web pages** (`src/webpage.ts`): only hosts in `ALLOWED_WEBPAGE_DOMAINS`, checked on the request and on every address the page lands on; an HTTP redirect is followed by the browser before we see it, so its request is made but its page refused. One `Bun.WebView` per fetch, created with `url`; `extractPage` waits for `load` (`loadEventEnd`, not `readyState`), then for the DOM to be quiet. The Chrome backend is `{ type: "chrome", url: false }` so a user's debuggable browser is never attached to; setting `process.env.BUN_CHROME_PATH` at run time has no effect.
- `POST /speech`: one utterance, at most 1,000 characters, only `zh`, `en`, `ja`, `es`, `ar` (others come out as noise). The voice id must be one `voices()` lists, never used to build a path otherwise. Markdown handling and sentence splitting are the client's (`public/speech-text.ts`), whose language list must match `SPEECH_LANGUAGES` in `src/speech.ts`.

## Configuration

Every setting is an environment variable with a lowercase-dashed flag that wins (`PORT` / `--port`);
defaults in `src/config.ts`, whose `SETTING_NAMES` lists them, so a new one goes there too. Unknown
arguments fail startup. Non-obvious ones:

- `ALLOWED_ORIGINS`: `scheme://host[:port]` or `scheme://*.host[:port]` (subdomains only); no bare `*`, no path (`src/access.ts`). `ALLOWED_HOSTS`: extra `Host` names, needed when `HOST` is `0.0.0.0` or `::`
- `ALLOWED_WEBPAGE_DOMAINS`: hosts `POST /webpage` may open: `name`, `*.name` (subdomains only) or a bare `*` (allowed here: the server makes the request); any port; empty (the default) turns it off
- `GPU_LAYERS`: `all`, a count, or `0` for CPU. `MTP=0`: no multi-token prediction (otherwise on where the GPU allows, see Invariants). `SPEECH=0`: reading aloud unavailable, libaudiocpp never loaded. `SPEECH_IDLE_UNLOAD=0`: never unload. `SPEECH_BACKEND=cpu` is far slower than real time
- `SPEECH_MODEL_DIR` / `SEPARATION_MODEL_DIR` / `TRANSCRIBE_MODEL_DIR` hold one GGUF each; no separation model means no separation. `VOICES_DIR` holds one `*.wav` per voice. `TRANSCRIBE=0`: `POST /transcriptions` unavailable
- `SEGMENT=0`: `POST /segment` unavailable. `ONNXRUNTIME_DIR` (default `vendor/onnxruntime`), `SEGMENT_MODEL_DIR` (`model.onnx` and `tokenizer.json`), `SEGMENT_THREADS`, `SEGMENT_IDLE_UNLOAD` (both also LaBSE's). `ALIGN=0`: `POST /align` unavailable; `ALIGN_MODEL_DIR` (`model.onnx`, `vocab.txt`, `dense.safetensors`). With both off ONNX Runtime is never loaded

## API

Spec: `docs/openapi.yaml` (served at `/api/v1/openapi.yaml`). After editing it run `bun run gen:api`: `src/api-schema.d.ts` (committed, generated, excluded from lint and format; CI fails when stale) holds its types, `src/api.ts` names them. The server builds every response as its schema's type and `public/` and the tests read bodies as these types, so a spec change shows up as a type error; no `any` crosses the API. `test/api-contract.test.ts` and `test/openapi.test.ts` keep only what types cannot say; do not re-add a test that the types already enforce.

- `POST /webpage` (`{ url }` → `{ url, title, markdown }`): never queues with translations; at most `MAX_WEBPAGE_FETCHES` (2) at once (`429 queue_full`), 60 s each. When `/health` `webpage.status` is `available` and the box holds one address, Translate asks in a dialog (Cancel, Translate as text, Fetch page). `startApp`'s fourth argument is the `WebpageFetcher` (tests pass the mock in `test/helpers/mock-engine.ts`).
- `POST /segment` (`{ texts }` → `{ texts: [{ offsets, probabilities }] }`): at most 256 texts and `MAX_SEGMENT_CHARS` (20,000) UTF-16 units in all (`GET /health` `segment.max_chars`). `startApp`'s fifth argument is the `SegmentLauncher` (the mock answers 0.95 after sentence punctuation, 0.01 after clause punctuation).
- `POST /align` (`{ unit?, source, target }` lists of sentences, the default, or `unit: "paragraphs"` → `{ pairs: [{ source, target, similarity }] }`, every item in exactly one pair, in order): at most 256 items a side; sentences at most `MAX_ALIGN_CHARS` (20,000) in all; `GET /health` `align` like `segment`; `503 align_unavailable`, failures `502 segment_error`. The mock pairs item i with i, or answers `mockAlign.pairs`.
- `POST /transcriptions` (WAV body, `?separate=`) answers an event stream (`start`, `stage`, `segment`, `done`; `X-Transcription-Id`); `GET /transcriptions/{id}/events`, `DELETE /transcriptions/{id}`; `/health` `transcribe`. Errors before the stream: 400, 413, 415, 429, `503 transcribe_unavailable`; in it, `speech_error` or `cancelled`. The mock (`mockSpeech.segments`, `segmentDelayMs`, `transcribeFailWith`) answers like the worker.
- `POST /translate` takes `text` or `image` (`text` then only a hint, `genre` refused); the image does not count towards the 4 MiB body limit. `POST /tokenize` never queues or swaps. `POST /speech` answers WAV, or with `Accept: audio/ogg` (named, not `*/*`) an Ogg Opus stream (`audio/qoa` is no longer sent, but stays in the spec: asking for it gets WAV); speed is `duration_factor` = 1/speed, range 0.5 to 2. `POST /voices` limits: `validateSample` in `src/speech.ts`. `DELETE /voices/{id}` forgets an uploaded voice only (`removeVoice`; an installed one is a 404): it leaves the list at once and its file is closed when no utterance still reads it.

- **Subtitles** (`subtitles.ts` pure, `subtitle-dom.ts`, `format.ts`, `css/subtitles.css`): a text `parseSrt` reads is SubRip (`formatOf`: before Markdown), shown in Preview as a `<table>` of cues whose rows carry `data-line` (the line of the cue's number); code that looks for `data-line` goes through `lineElements` / `lineElementOf` (`dom.ts`), not `view.children`. While streaming, an entry with no text yet is not joined (no stretching row). `subtitleAlignment` finds the groups again from the two SubRip texts alone (index and start, then end), for click-to-sync at the end of a run, after Stop and on restore (history keeps no `blocks` for subtitles); no paragraph check, `POST /align` or link check. **Chunks**: one request of 266 or 335 cues looped back at about the 200th–250th cue and en→zh text drifts up to 3 cues late by a run's end, so `planChunks` cuts the sent cues into requests of at most `CHUNK_LIMITS` (cues, letters), each numbered 1..n again (`chunkText`), the next starting `overlap` cues before the previous one ends (moved up to half that earlier to a sentence's or a scene's start); the page sends them one after another (`streamSubtitles`, `Run.nextJob`, "Part k of n"), and a chunk that does not finish with `stop` ends the run. `translateSubtitles` takes every chunk's output and passes from one chunk to the next in their overlap (`cutAt`): at a number where both start an entry with text, preferring a sentence start near the overlap's middle; with none, after the overlap; while the next chunk is still within the overlap, the earlier chunk is shown. Constants measured with `scripts/longsubs.ts`; no advice about length any more. Reading aloud reads cue by cue (`cueBlocks` in `speech-text.ts`, a short pause unless the cue ends a sentence). **Speakers**: when every cue with text starts with `label:` (or `label：`), and either all labels are ids `S\d+` (any number: a 442-cue film transcript had 24) or there are at most 12 and one repeats (`speakerColumn`), the table has a Speaker column (`cue-meta`, so neither hover nor reading aloud sees it) and reading aloud skips the labels. Only ids are taken off in `toWire` (`Wire.speakers`) and put back by `translateSubtitles` (`withSpeakers`: a joined group of several speakers gets `S01 / S02:` on its first line, since which words are whose is unknown); a name label stays in the text for the model to translate.

- **Service worker** (`sw.ts`, `pwa.ts`): never serves a stale file. No-op (no fetch handler, caches dropped) on loopback. Elsewhere it first fetches `/asset-manifest.json` (URL path → ETag of every file in `public/`, built by `static.ts` at launch and rebuilt on the next request after a change seen by the shared `public-watch.ts` watcher, which dev reload also uses), serves a cached file only when its stored `ETag` header equals the listed one, otherwise downloads it (normal priority) and caches it, so a file is cached once the page has asked for it (the bulk download of every missing or outdated file at low priority is switched off, `if (false)` in `prefetch`: `bun run e2e:perf` showed it only speeds up the second visit, at 12 MB on the first), and a page load fetches the list again. `/api/`, `/__dev/`, unlisted paths and range requests go to the network. One `AudioContext` created in the click; pause is `suspend()`. A new translation, Clear, switching the source to Raw or changing From stops the reading.
  - **Read-from gutter** (`read-gutter.ts`): Read aloud is an `aria-pressed` toggle that starts nothing: it shows a column of "Read from: …" buttons, one per spoken block; released, it hides the column and stops. Targets are ≥ 24 px (2.5.8), not 44: one-line blocks are shorter.
- **Opus stream** (`public/opus.ts`, `src/opus-stream.ts`, `src/opus-ffi.ts`): the page probes once whether `OfflineAudioContext.decodeAudioData` decodes an embedded Ogg Opus file (not `canPlayType`; the file was made by our encoder) and, if so, sends `Accept: audio/ogg, audio/wav;q=0.5`, otherwise no `Accept` (WAV). The server resamples with libsoxr, encodes with libopus (CELT only, `OPUS_APPLICATION_RESTRICTED_CELT`, complexity 6: the tonality analysis above 6 did nothing measurable for speech; one encoder per response, freed when the stream ends or is cancelled) and muxes with `public/ogg-opus.ts`. `opus_encoder_ctl` is variadic: bound twice with fixed signatures (int or pointer argument), which holds on x86-64 and Linux aarch64. `opusLoader` answers undefined when `vendor/opus` is missing, so WAV is sent. e2e's mock server points `audioDir` at the real `vendor/audio.cpp` only so `vendor/soxr` and `vendor/opus` are found; tests that want WAV remove `OfflineAudioContext` (`withoutOpus`). - **Transcribing a recording** (`transcribe-flow.ts`, `media-file.ts` and `matroska.ts` pure, `transcription.ts` pure, `transcode.ts` + `pcm.ts` pure for re-encoding): `open-file.ts` kind `media` (`.wav .ogg .oga .opus .webm .mkv .mka`, offered while `/health` `transcribe` is available; `OpenUi.setMedia`). `probeMedia` sniffs the first bytes and lists the audio tracks; the dialog is `ask()` with `fields` (radios when there are several tracks, a disabled one with its reason; the separation select when installed). (Playwright's Chromium decodes all of these but AC-3; Chromium hands decoded channels in WAV/SMPTE order, which `STEREO_MIX` assumes). Output: Ogg Opus by a streaming `OggOpusEncoder` (`audio-upload.ts`, 64 kbps mono / 128 kbps stereo; stereo kept because RoFormer separation uses it, more channels mixed down by ITU weights) where the server takes Ogg and `AudioEncoder` encodes it, else a mono 44.1 kHz 16-bit WAV (30 minutes are 159 MB, under 160 MiB; 16 kHz would hurt separation) capped at `max_bytes`. `Resampler` is our own windowed sinc (not relying on the encoder resampling). `PcmTimeline` places each decoded chunk by its timestamp: before 0 dropped (AAC and MP3 priming come out at negative times; Chromium trims Opus pre-skip itself), gaps ≥ 10 ms filled, late start as in the remux. Waits on a full codec queue take its `dequeue` event (`dequeued`; a codec without `ondequeue` yields a task through a `MessageChannel` instead, never `setTimeout(0)`, whose 4 ms clamp made 30 minutes take 40 s instead of 2–13 s; never a microtask, which lets no codec callback run). A Matroska file at most `CUT_SLACK_SECONDS` past `max_seconds` is not called cut. Firefox and Safari untested.
