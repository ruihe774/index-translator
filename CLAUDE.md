# CLAUDE.md

Local translation app. One Bun process serves the REST/SSE API and the static web app, and runs three engines
in-process through `bun:ffi`, each on its own worker thread: llama.cpp (libllama, Vulkan; one model at a time; the
chat model also translates images through libmtmd), audio.cpp (IndexTTS-2.5 reading aloud, Mel-Band RoFormer voice
separation, and a preview of transcription: CED, Silero VAD and MOSS-Transcribe-Diarize) and ONNX Runtime on CPU
(`POST /segment`: SaT sentence ends; `POST /align`: LaBSE embeddings and AIlign's DP). `POST /webpage` opens a page in
a headless browser (`Bun.WebView`) and answers Markdown. User docs: README.md. On Windows read `WINDOWS.md` first.

## Commands

Use Bun canary (`bun --revision` must end in `-canary…`; `lint:ts` needs its builtins). Cloud session without it: `curl -fsSL -o /tmp/bun.zip https://github.com/oven-sh/bun/releases/download/canary/bun-linux-x64.zip && unzip -qo /tmp/bun.zip -d /tmp/bun && install -m755 /tmp/bun/bun-linux-x64/bun ~/.bun/bin/bun`.

Run `bun install` before `lint:*` or `e2e` when `node_modules` is missing or stale.

- Run: `bun src/server.ts` (`--help` lists every setting). Dev: `bun run dev` (also `ALLOWED_WEBPAGE_DOMAINS='*'`)
- Test: `bun test` (mock engine, no GPU). E2E/a11y: `bun run e2e` (Playwright, mock engine; `e2e/README.md`; `bunx playwright install chromium` or `CHROMIUM_PATH`)
- Coverage: `bun run test:coverage`, `bun run e2e:coverage`; workers are not measured. Page load times on a throttled link: `bun run e2e:perf` (asserts nothing)
- Lint and typecheck: `bun run lint:ts` (`bun lint`: builtin linter and type checker, no `tsc`; each file uses its nearest `tsconfig.json`; config under `[lint]` in `bunfig.toml`). Errors and warnings stay at zero. Suppress with `// eslint-disable-next-line <rule> -- <why>` (a `: <why>` suffix suppresses nothing). **If a change introduces lint errors or warnings, tell the user which rules failed, even if you then fix them** (the user audits the rules).
- JS browser support: `bun run lint:es` (ESLint with `eslint-plugin-browser-compat` against `.browserslistrc` and `eslint-plugin-es-x` up to `ES_EDITION` in `scripts/lint_es.ts`). It lints what `public/*.ts` becomes under `Bun.Transpiler`: `bun:*` and `*.json` imports are errors. Bun strips comments, so `eslint-disable` in `public/` does nothing: an exception goes in `scripts/lint_es.ts` (`settings.polyfills` or a rule override) with a comment why.
- Format: `bun run format:write` / `format:check` (120 columns; Markdown is hand-formatted). DO NOT USE prettier
- CSS: `bun run lint:css`. Markdown conformance: `bun scripts/commonmark.ts`. Long documents: `MODEL=index-nailong-9b bun scripts/longtext.ts <url>`; long subtitles: `bun scripts/longsubs.ts <url> [out-dir]`

Setup (Linux and Windows):
- `bun scripts/build_llama.ts`: libllama, libmtmd, Vulkan, one CPU backend (AVX2 on x86-64, Armv8.2-A+dotprod+fp16 on aarch64, unless `--native`), `libllama-shim.so` into `vendor/llama.cpp` (`--shim` only recompiles `src/llama-shim.c` and `src/llama-shim-ext.cpp`; a build from before MTP lacks `include/llama-ext.h` and needs the full build)
- `bun scripts/build_audiocpp.ts`: `vendor/audio.cpp/libaudiocpp.so` from the pinned commit (a commit on main, plus a Vulkan Flash Attention change for RoFormer from `ruihe774/audio.cpp` until upstream merges it) plus `scripts/patches/audiocpp-abort.patch` and `audiocpp-custom-output.patch`, in that order (AVX2 unless `--native`), and Silero VAD's weights beside it
- `bun scripts/build_soxr.ts`: `vendor/soxr/libsoxr.so.0` (`soxr.dll`); required, opened before libaudiocpp (see Invariants)
- `bun scripts/build_libopus.ts`: `vendor/opus/libopus.so.0` (`opus.dll`) from the pinned commit; the speech stream's Opus encoder (without it speech is WAV) and the Ogg Opus upload decoder (without it uploads are WAV only)
- `bun scripts/fetch_models.ts`: models (about 19.2 GiB) and example voices; `--model <id>`, `HF_ENDPOINT`. Includes `sat-3l-sm` (`/segment`), `labse` (`/align`) and `moss-transcribe-diarize` (`/transcriptions`)
- `bun scripts/fetch_onnxruntime.ts`, `fetch_web_libs.ts` (PDF, undoc, Temml with Noto Sans Math), `fetch_turndown.ts`: each fills a `vendor/` or `public/vendor/` directory (not in git, pinned by checksum); `POST /segment`, `/webpage`, PDF and Word are unavailable or their tests skipped without them (equations show as TeX), and packaging requires all of them
- `bun scripts/build_appimage.ts`, `bun scripts/build_installer.ts` (need both engines built; `WINDOWS.md`)
- CUDA variant (Linux x86-64 and aarch64, AppImage only): `build_llama.ts --cuda`, `build_audiocpp.ts --cuda`, `build_appimage.ts --cuda` (CUDA 13 toolkit via `CUDA_PATH` or `/usr/local/cuda-13`). One GPU backend per variant, never both: CUDA builds have no Vulkan (`vendor/llama.cpp-cuda`, `vendor/audio.cpp-cuda`, run with `LLAMA_DIR`, `AUDIO_DIR`, `SPEECH_BACKEND=cuda`); `build_appimage.ts` refuses a mixed pair. CUDA runtime libraries sit beside each engine library (`$ORIGIN`); `AppRun` sets `SPEECH_BACKEND=cuda`. CI: job `appimage-cuda` (manual only)

No npm runtime dependencies; no build step for the web app.

## Layout

- `src/`: `server.ts` entry; `app.ts` the route table; its parts: `parse.ts` (request bodies), `http.ts` (`ApiError`, error mapping, JSON), `translate.ts` (prompt budget, generation as events), `jobs.ts` (streamed jobs of translations and transcriptions, resume), `tickets.ts` (an engine's waiting line), `health.ts`, `speech-response.ts` (WAV or Opus); `config.ts`; `static.ts` (`.ts` in `public/` transpiled on request); `queue.ts`; `preflight.ts` + `llama-probe.ts`; `models.ts`; `prompt.ts` (NativeLong templates); `image.ts`
- Engine pairs, server + worker: `llama.ts` / `llama-worker.ts` (`llama-ffi.ts` bindings, `llama-shim.c` struct calls and the MTP drafter, `llama-shim-ext.cpp` C names for `llama-ext.h`); `speech.ts` / `speech-worker.ts` (`audiocpp-ffi.ts`, no C shim; `transcript.ts` the engine-free parts of a transcription); `segment.ts` / `segment-worker.ts` (`onnxruntime-ffi.ts`, `sat.ts`, `labse.ts`, `align.ts`; none of the last three touch the runtime); `cpu.ts` thread counts; `opus-stream.ts` (`opus-ffi.ts`), `opus-file.ts` (Ogg Opus uploads), `resample.ts`, `accept.ts`, `wav.ts`; `public/ogg-opus.ts` (Ogg muxer and demuxer, shared with the page: no Bun, no DOM; listed in the root `tsconfig.json`; `src/` imports it as `../public/ogg-opus`)
- `webpage.ts` (`POST /webpage` through `Bun.WebView`) + `page/extract.ts`, which runs inside the fetched page (own `tsconfig.json` with the DOM; read as text, types stripped, sent after turndown; a script, no imports)
- `public/`: web app. `state.ts` + `render.ts` hold the state behind the always-shown controls and the one synchronous `render()` (callers move focus right after `setState`); `elements/` light-DOM custom elements enhancing `index.html`; `css/` one file per feature, `style.css` only the layer order and `@import`s
- `e2e/mock-server.ts`: real app on the `test/helpers/mock-engine.ts` mocks, scriptable via a control port. Fixtures in `test/fixtures/` (`sample.pdf`: `uv run make_sample_pdf.py`; `sample.docx`: `make_sample_docx.py`; `media/`: `bun test/fixtures/make_media.ts`, needs ffmpeg and mkvmerge; a rerun rewrites every file with other bytes, so keep the ones a change does not need; `test/helpers/ebml.ts` writes the Matroska edge cases by hand)

## Invariants

### Engines and queues

- The backend never picks a model from the text; the client does (`public/select-model.ts`). `LONG_THRESHOLD_LETTERS = 11_000` there is the switch point (the chat model loses paragraphs beyond about 11–16K letters); keep docs in sync.
- A model swap frees the loaded model and loads the other; repeated requests do not reload.
- libllama is only called from its worker thread, and every call blocks it. Threads: `LLAMA_THREADS`, else `inferenceThreads` (`src/cpu.ts`): `min(performance cores, navigator.hardwareConcurrency, 8)` (ggml waits for its slowest thread, so E-cores slow the P-cores down). `SEGMENT_THREADS` has the same default; nothing shares out the cores between the two. A generation returns to the worker's event loop after each decode, which is when `/tokenize` and cancellations are handled.
- The engines (llama.cpp, audio.cpp, ONNX Runtime) share the process: a crash in any takes the server down.
- Generation is greedy from an empty context. One at a time; up to `MAX_QUEUE` wait FIFO, beyond that `429 queue_full`. Closing the client connection cancels it, except for an SSE request with `resumable: true`: that job (`Job` in `src/jobs.ts`) runs on for `RESUME_GRACE_MS` with no reader, can be read again by `GET /translations/{id}/events` (`Last-Event-ID`) and is cancelled by `DELETE /translations/{id}`; finished ones are kept 10 minutes.
- `MAX_INPUT_TOKENS + 64 < CTX_SIZE`, else startup fails. Output is capped at 4 × prompt tokens + 512 unless `max_output_tokens` is set.
- No authentication: keep `HOST` on loopback or behind a proxy; `ALLOWED_ORIGINS` / `ALLOWED_HOSTS` control access.
- `src/server.ts` runs `preflight` first and exits 1 with one message when the machine cannot run the translator: libraries do not open (checked in a separate process), no CPU backend, no Vulkan GPU while `GPU_LAYERS` is not `0` (CPU-type devices such as lavapipe do not count), or the default model's file is missing. `startApp` does not check; tests and e2e use the mocks.
- Request bodies are read with `readBody` (`parse.ts`), which stops at the route's limit: `MAX_REQUEST_BYTES` is the largest route's (a transcription) and a chunked body declares no length.
- **QoS on Windows** (`src/qos.ts`): the server has no windows, so Windows may put its threads on E-cores. `GET /health?visible=true` from a loopback address renews a lease of `QOS_LEASE_MS` (15 s) during which the process opts out of execution-speed throttling; at expiry or `stop()` the masks are cleared. The page sends it with every poll and polls only while `document.hidden` is false. `startApp`'s sixth argument is the setter (tests pass a recorder); undefined elsewhere than Windows.

### llama.cpp: prompt, MTP, images

- The prompt is written by `chatPrompt` (`src/llama-ffi.ts`), not the Jinja template: ChatML, token-identical to the template with `enable_thinking=false`. A non-ChatML template fails to load.
- **Multi-token prediction** (MTP; `Model.next`, `shim_mtp_*` in `src/llama-shim.c`): for a `ModelSpec` with `mtp` (the chat model; NativeLong not), `MTP` not `0`, `GPU_LAYERS` all and total GPU memory ≥ `MTP_MIN_GPU_BYTES` (15.5 GiB, so a 16 GiB card qualifies), decided at load. The model's MTP layer drafts `MTP_DRAFT` (2) tokens in a context of type MTP; one decode of the target checks them; greedy matching keeps the target's own choices, and `llama_memory_seq_rm` drops the rest from both contexts (the target is created with `n_rs_seq = MTP_DRAFT` so its recurrent layers can roll back). Every text decode is followed by `shim_mtp_catch_up` (the MTP layer reads the target's hidden state via `llama-ext.h`, C names in `llama-shim-ext.cpp`). Ported from llama.cpp's `common/speculative.cpp`. Text prompts only: after an image the worker decodes one token at a time. Output can differ from token-at-a-time decoding at near-ties, never by a confident choice; check with a teacher-forced comparison after changing it.
- **Image input** (`image` on `POST /translate`, chat model only):
  - Every upload is decoded by `Bun.Image` and re-encoded as an uncompressed PNG (`prepareImage`, before the queue); JPEG, PNG, WebP only, 8 MiB, 50 million pixels. It is resized once to the size libmtmd would pick (`engineSize`), so libmtmd copies it without resampling.
  - The shim decodes with libmtmd's own `stbi_load_from_memory`, not `mtmd_helper_bitmap_init_from_buf`, which drops alpha: transparency becomes white (dark text would otherwise be black on black).
  - The prompt is `buildImagePrompt`, then the image: `imageChatPrompt` splits `chatPrompt` there and `mtmd_tokenize_from_parts` puts the image between `<|vision_start|>` and `<|vision_end|>`. No media marker, so one in the text is text.
  - M-RoPE: an image takes `max(rows, columns)` positions, not its token count. After an image prompt the worker decodes with explicit positions (`shim_decode_at`, `Model.nextPos`); `llama_batch_get_one` would continue one past the image's first position.
  - The mmproj GGUF (`ModelSpec.mmproj`) is loaded by the first image and freed with the model. Missing: `503 image_unavailable`. Counting an image's tokens means preparing it, so it goes through the worker's chain and `/tokenize` refuses images.

### Segmentation and alignment (ONNX Runtime)

- **Sentence segmentation** (`src/segment.ts`): ONNX Runtime is only called from the segmentation worker, started by the first `POST /segment` or `POST /align` (never at startup); freed after `SEGMENT_IDLE_UNLOAD` seconds idle; a failed load is retried. `onnxruntime-ffi.ts` reads function pointers from `OrtApi` by slot, no C shim; strings and arrays the library keeps pointers to must stay referenced from JS. `sat.ts` is wtpsplit's SaT with tokens identical to Hugging Face's XLM-R tokenizer. Offsets are UTF-16 units of the text as sent. Own single-slot queue, like speech.
- **Sentence alignment** (`POST /align`, `src/align.ts`, `src/labse.ts`): LaBSE is the segmentation worker's second ONNX session, same queue, own load state (`ModelSlot`) and idle unload; `ALIGN=0` turns it off. The quantized model ends at `last_hidden_state`, so the embedding is ours: [CLS] through sentence-transformers' Dense (768 → 768, tanh), L2-normalized; the WordPiece tokenizer must stay identical to Hugging Face's (`test/labse-native.test.ts`). `align.ts` is the DP step of the AIlign paper (arXiv:2403.11921, CC BY 4.0) written from the paper, never from its CC BY-NC code. `unit: "paragraphs"` embeds each paragraph by its opening and measures length by what it translates (`translatedLengths`); an empty side costs 0.7; no 2-2 group.

### Speech (audio.cpp)

- libaudiocpp is only called from the speech worker, started by the first `POST /speech` (never at startup); freed after `SPEECH_IDLE_UNLOAD` seconds idle. A failed load is retried by the next request.
- libaudiocpp must link its ggml statically and export only `audiocpp_*`. audio.cpp's ggml is a fork with the same SONAME `libggml.so.0` as llama.cpp's; shared ggml binds to the loaded libllama and dies with an undefined symbol.
- libsoxr: audio.cpp `dlopen`s `libsoxr.so.0` / `soxr.dll` by bare name and otherwise falls back to a resampler that sounds different, so `openSoxr` (`src/audiocpp-ffi.ts`) opens our `vendor/soxr` build by full path before libaudiocpp. A missing build is an error, not a fallback. Changing the audio.cpp pin: recheck the lookup names and the `soxr_*` symbols.
- Aborting an utterance: our patch adds `audiocpp_set_abort_flag` (checked before every decoding step, diffusion step and the vocoder). Each `synthesize` message carries its own 4-byte `SharedArrayBuffer`, set on client abort; the worker answers `aborted`. The request is answered at once but keeps its queue slot until that answer. Not stoppable: conditioning before the first step, a model load, a separation.
- Uploaded voice samples are separated by Mel-Band RoFormer (`POST /voices` → worker `separate`) when a `.gguf` is in `SEPARATION_MODEL_DIR`; otherwise kept as uploaded. Speech and separation models are never loaded together (`separating` is the gate). Failure is `SeparationError` (`502 speech_error`), never a fallback to the unseparated sample.
- Speech has its own single-slot queue and never holds the translation queue; both may use the GPU at once.
- `POST /speech`: one utterance, at most 1,000 characters, only `zh`, `en`, `ja`, `es`, `ar` (others come out as noise). The voice id must be one `voices()` lists, never used to build a path otherwise. Markdown handling and sentence splitting are the client's (`public/speech-text.ts`), whose language list must match `SPEECH_LANGUAGES` in `src/speech.ts`.

### Transcription

- **Transcription** (`POST /transcriptions`, a preview; `speech.transcribe`, worker `transcribe`): on the speech worker and in the speech queue; it frees the speech model and holds the same GPU gate as a separation (`alone` in `speech.ts`), so reading aloud waits for it. Needs the engine and MOSS, not IndexTTS (`TRANSCRIBE`, not `SPEECH`). Worker pipeline: optional separation (`separate=auto|true|false`; `auto` = the model is installed, and only stretches where CED-tiny on the CPU hears music (`musicRegions`) are separated with RoFormer's `num_overlap` 1 (`TRANSCRIBE_SEPARATION_OVERLAP`; voice samples keep 2) and spliced over the 16 kHz mono so times do not move; `true`, or `auto` without CED's file: the whole recording), mono at 16 kHz, `normalizeLoudness(…, true)`, Silero VAD on the CPU, a cut to the speech only when more than `TRIM_SILENCE_SHARE` (30%) is silence, then MOSS in a *streaming* session. Its text is read piece by piece (`SegmentReader`), each complete segment is posted with its times mapped back (`toOriginal`), and the abort flag is checked between pieces and separation stretches; the prefill and a stretch being separated are not stoppable.
  - MOSS fails the run with "reached max_tokens" at its budget and loses the text; read as it is written, what came before stands (`truncated`). `maxTokens` is VRAM: audio.cpp reserves the cache for the prompt plus the budget.
  - MOSS repeats itself on music: `LoopGuard` stops it (six identical segments, or one starting past the end), and so does a segment still open after 1,000 characters (`SegmentReader.runaway`). Stopped before any segment (e.g. a song without separation: MOSS writes only times and speaker tags), the run is a `speech_error`, not an empty `done`.
- **Transcription jobs** (`TRANSCRIPTION_JOBS` in `jobs.ts`): always resumable and never cancelled for lack of a reader; kept 30 minutes after they end, at most 16; `DELETE` cancels and forgets (a reader still gets `cancelled`). The body is a WAV or Ogg Opus file of at most `MAX_TRANSCRIBE_BYTES` (160 MiB), checked from its header before it is queued (`validateRecording`, `readRecordingInfo`), then kept in an anonymous file that the worker reads by descriptor and the job closes when it ends however it ends (also on a 429). Translation jobs keep their 2-minute grace and 10-minute keep.
- **Uploads in Ogg Opus** (`src/opus-file.ts`): `POST /voices` and `POST /transcriptions` take `audio/wav` and, when libopus is installed, `audio/ogg` (`uploadTypes`, listed as `upload_types` in `GET /voices` and `/health` `transcribe`; the declared type picks the parser, so an Ogg file sent as WAV is a 400). `demuxOggOpus` (`public/ogg-opus.ts`) reads a subset of Ogg: one logical stream, family 0, from granule 0; it checks every page's CRC and sequence and that the last granule fits the packets' TOC durations, so the length is bounded before anything is decoded. A voice sample is decoded on the main thread, resampled to 44.1 kHz with libsoxr and kept as a 16-bit WAV (`opusSampleToWav`), so the voice path only knows WAV; a recording to transcribe is decoded by the worker (`readRecording`).
- **Uploads on disk** (`src/anonymous-file.ts`): voice samples and recordings are written to a file in the first of `TMPDIR`, `/var/tmp` (on disk; `/tmp` is often a tmpfs, so RAM) and `os.tmpdir()` where creating and writing works, and unlinked at once; only the descriptor reaches it (the worker reads it by `fd`), and the system frees it on `close()` or process end, a crash included. On Windows `/var/tmp` is skipped.

### Web Push

- **Web Push** (`src/push.ts`, opt-in: on only when `PUSH_CONTACT` is set): a resumable job may hold a subscription (`PUT /translations/{id}/push`, `/transcriptions/{id}/push`); `finishJob` sends one `PushMessage` when the job ends done or failed with no reader attached (never for a cancel), TTL its keep time. Its `text` is the error's message, or the result's ends: `Preview` keeps the first and last pieces of what `JobKind.textOf` takes from each event (`delta`, `segment`), cut by grapheme (`Intl.Segmenter`), back to a space when a cut splits a word (pieces are tokens), shown whole when short. Payload encryption is RFC 8291 `aes128gcm` (`test/push.test.ts` pins the RFC's example), the token VAPID (RFC 8292) with `PUSH_CONTACT` as `sub`; all WebCrypto, no account with any push service. The VAPID key lives in memory: a restart changes `/health` `push.public_key`. The server POSTs to a client-given URL, so endpoints are limited to the browsers' push services (`PUSH_HOSTS`), https, default port. `startApp`'s seventh argument is the `PushLauncher` (tests pass a recorder). The Windows launcher has no switch for it yet (needs a Windows build).

### Web pages

- **Web pages** (`src/webpage.ts`): only hosts in `ALLOWED_WEBPAGE_DOMAINS`, checked on the request and on every address the page lands on (the browser follows an HTTP redirect before we see it, so its request is made but its page refused). One `Bun.WebView` per fetch, created with `url`; `extractPage` waits for `load` (`loadEventEnd`, not `readyState`), then for the DOM to be quiet. The Chrome backend is `{ type: "chrome", url: false }` so a user's debuggable browser is never attached to; setting `process.env.BUN_CHROME_PATH` at run time has no effect.

## Configuration

Every setting is an environment variable with a lowercase-dashed flag that wins (`PORT` / `--port`);
defaults in `src/config.ts`, whose `SETTING_NAMES` lists them, so a new one goes there too. Unknown
arguments fail startup. Non-obvious ones:

- `ALLOWED_ORIGINS`: `scheme://host[:port]` or `scheme://*.host[:port]` (subdomains only); no bare `*`, no path (`src/access.ts`). `ALLOWED_HOSTS`: extra `Host` names, needed when `HOST` is `0.0.0.0` or `::`
- `ALLOWED_WEBPAGE_DOMAINS`: hosts `POST /webpage` may open: `name`, `*.name` (subdomains only) or a bare `*` (allowed here); empty (the default) turns it off
- `GPU_LAYERS`: `all`, a count, or `0` for CPU. `MTP=0`: no multi-token prediction. `SPEECH=0`: reading aloud unavailable, libaudiocpp never loaded. `SPEECH_BACKEND=cpu` is far slower than real time
- `SPEECH_MODEL_DIR` / `SEPARATION_MODEL_DIR` / `TRANSCRIBE_MODEL_DIR` hold one GGUF each; no separation model means no separation. `VOICES_DIR` holds one `*.wav` per voice. `TRANSCRIBE=0`: `/transcriptions` unavailable
- `PUSH_CONTACT`: the VAPID `sub`, a URI (`mailto:`, `https:`, ...); setting it turns Web Push on, unset is off (it reaches the browser vendor's push service); no default
- `SEGMENT=0`: `/segment` unavailable; `ALIGN=0`: `/align` unavailable (both off: ONNX Runtime is never loaded). `ONNXRUNTIME_DIR`, `SEGMENT_MODEL_DIR` (`model.onnx`, `tokenizer.json`), `ALIGN_MODEL_DIR` (`model.onnx`, `vocab.txt`, `dense.safetensors`); `SEGMENT_THREADS` and `SEGMENT_IDLE_UNLOAD` are also LaBSE's

## API

Spec: `docs/openapi.yaml` (served at `/api/v1/openapi.yaml`). After editing it run `bun run gen:api`: `src/api-schema.d.ts` (committed, generated, excluded from lint and format; CI fails when stale) holds its types, `src/api.ts` names them. The server builds every response as its schema's type and `public/` and the tests read bodies as these types, so a spec change shows up as a type error; no `any` crosses the API. `test/api-contract.test.ts` and `test/openapi.test.ts` keep only what types cannot say; do not re-add a test that the types already enforce.

- `POST /translate` takes `text` or `image` (`text` then only a hint, `genre` refused); the image does not count towards the 4 MiB body limit. `POST /tokenize` never queues or swaps.
- `POST /webpage` (`{ url }` → `{ url, title, markdown }`): never queues with translations; at most `MAX_WEBPAGE_FETCHES` (2) at once (`429 queue_full`). `startApp`'s fourth argument is the `WebpageFetcher` (tests pass the mock).
- `POST /segment` (`{ texts }` → `{ texts: [{ offsets, probabilities }] }`): at most 256 texts and `MAX_SEGMENT_CHARS` (20,000) UTF-16 units in all.
- `POST /align` (`{ unit?, source, target }` → `{ pairs: [{ source, target, similarity }] }`, every item in exactly one pair, in order): at most 256 items a side; sentences at most `MAX_ALIGN_CHARS` (20,000) in all; `503 align_unavailable`, failures `502 segment_error`.
- `POST /transcriptions` (WAV or Ogg body, `?separate=`) answers an event stream (`start`, `stage`, `segment`, `done`; `X-Transcription-Id`); `GET` / `DELETE /transcriptions/{id}`; `/health` `transcribe`. Errors before the stream: 400, 413, 415, 429, `503 transcribe_unavailable`; in it, `speech_error` or `cancelled`. The mock answers like the worker.
- `PUT /translations/{id}/push`, `PUT /transcriptions/{id}/push` (`PushSubscription.toJSON()` → 204): `503 push_unavailable` without `PUSH_CONTACT`; `/health` `push` carries `public_key`.
- `POST /speech` answers WAV, or with `Accept: audio/ogg` (named, not `*/*`) an Ogg Opus stream; speed is `duration_factor` = 1/speed, range 0.5 to 2. `POST /voices` limits: `validateSample` in `src/speech.ts`. `DELETE /voices/{id}` forgets an uploaded voice only (an installed one is a 404).

## Models

- `index-translate-9b` (chat): any language; glossary, constraints, genre; images through its mmproj (Q8_0).
- `index-nailong-9b` (NativeLong document): `zh-en`, `en-zh`, `zh-ja`, `ja-zh` only; `source_lang` required; glossary, constraints, genre rejected.

The separation GGUF embeds only a legacy spec, hence `AUDIOCPP_DEPLOYMENT_BUILD=ON`.

Limits: audio.cpp does not normalize digits in Japanese (`speech-text.ts` writes them in kanji) or Arabic
(garbled); German produced noise. NativeLong zh→en loses paragraph markers at full length (cause
unknown), so the client verifies them. Chat en→zh loses or repeats paragraphs by about 16K letters.

## Notes for changes

- UI changes keep `A11Y-ACCEPTANCE.md` (WCAG 2.2 AA) true and `e2e/a11y.spec.ts` green. Click-to-sync has no keyboard route (A11Y-13 FAIL). Anything that scrolls must be focusable while it overflows (`public/scroll-focus.ts`).
- The web app must keep working with the server's error codes (`public/errors.ts`) and the paragraph-loss check (`public/paragraphs.ts`).
- README.md is for user-visible behaviour only.

### Web app

- **Markdown**: output renders as Markdown only when the *source* passes `looksLikeMarkdown`. The parser is pure and prefix-stable (a block never changes once a later complete line starts another), which `MarkdownStream` relies on. Elements are built with the DOM API, never by parsing a string as HTML; links limited to `http(s):` and `mailto:`. Copy puts the raw text as `text/plain` and, when shown rendered, the built tree as `text/html` (`clipboardHtml`); the paragraph check uses the raw text. Top-level rendered elements carry `data-line`. Parser changes keep `bun scripts/commonmark.ts` passing and `docs/markdown-conformance.md` in step.
- **Equations** (`math.ts`, `css/temml.css`): `$…$`, `$$…$$` and `$$` blocks (rules in `docs/markdown-conformance.md`) become MathML by Temml's `render` (DOM API; `trust` off). Temml and its stylesheet (layer `temml`, after `components` so `cjk.css` fonts do not reach the MathML) load with the first equation; until then, without `public/vendor/temml`, or when Temml throws (it throws more than `ParseError`, e.g. on `x^`), the box shows the TeX. Every equation is a `.math` box: `text-groups.ts` skips it, so neither the sentence mark nor reading aloud sees it, and `speech-text.ts` speaks nothing for it; `clipboardHtml` keeps MathML attributes. The CSP blocks Temml's `data:` SVG masks (`\cancelto`'s arrow).
- **Link check** (`links.ts`, `checkLinks` in `markdown-dom.ts`): after a finished translation of a Markdown source, an output link target not in the source is disabled, one not in the matched blocks is marked a mismatch; clicking opens `link-dialog.ts`.
- **Layout**: text box, source preview and translation share one height (`--pane-height`). Switches, Clear and Copy are always shown, `aria-disabled` when idle. `#meta` is the one status line (errors `role="alert"`); warnings go in `#notes`. One width breakpoint, 54rem; below it (`css/phone.css`) `--pane-height` is tied to `100svh` less a fixed 12rem (iOS Safari's floating toolbar overlays the page), and model buttons show short names (`span.long` / `span.short`; a new model button needs both). There the two panels stay side by side in `#workspace`, a row that scrolls sideways with snapping (`pane-carousel.ts`, `css/pane-carousel.css`), and the `#pane-switch` under it does what a swipe does; Translate and an error bring the translation in, and when the row starts to move the panel coming in is scrolled to the counterpart of the block at the top of the other (`sync.follow`). A focus move that should not slide the row uses `preventScroll`.
- **Full view** (`full-view.ts`, `css/full-view.css`): `#full-source` / `#full-output` before each side's Read aloud, enabled while that side shows Preview (the translation also needs text), show its view alone in a reading column that the *page* scrolls (no scroller), under `.pane-bar` (sticky: `#full-view-exit` at the start, `#pane-switch` at the end at every width, both scaled 0.75 and grey); its own grey `--bg` (`light-dark(#ffffff, #101010)`), `--text` and `--muted`, `--text-size` 1.25rem at every width, and, in the text, `--surface` a mix of `--text` into `--bg`. `data-full-view` on the root names the side. The switch turns the other side to Preview and scrolls to the counterpart of the block under the bar (`counterpart`), else the same share. Entering stops reading aloud and pauses the player; their gutters are hidden. Exit, Escape and Back leave (entering pushes a same-URL history entry); the page and the pane are put back. The carousel is held meanwhile (`PaneCarousel.hold`). Code that scrolls a pane to its end goes through `scrollToEnd` (`app.ts`).
  - **Side by side** (`data-full-view="both"`, the switch's middle button `both`): shown only in full view at ≥ 54rem, enabled only for matched blocks (`sync.active()`) that are not subtitles; when that stops (narrower, unmatched) full view goes to the source at the block that was at the top (`sourceTop`, kept on scroll: the columns reflow before the media query fires). The workspace is a two-column grid; `.panel`, `.source-field`, `.output-area` and `.output` are `subgrid` rows, and `sideBySideRows` (`side-by-side.ts`, pure) gives each `lineElements` block its `grid-row` from the `Alignment`, joining groups one element spans (a list in `lines` unit) into one band; a `MutationObserver` reapplies it when a view is rebuilt. Leaving goes back to the side full view was opened on.
  - **Transitions** between the three: `document.startViewTransition` where it exists (in `lint_es.ts` `settings.polyfills`) and motion is not reduced, else at once. Only blocks in view get a `view-transition-name` (`full-<side>-<line>`, class `source` / `output`), removed when it ends; pictures keep their own size (not stretched), a side alone slides from or to its end of the strip; `.pane-bar` has its own name.
- **CJK typography** is `:lang(ja)` / `:lang(zh)` in `css/cjk.css`, so the textarea, source preview and output must carry the `lang` of their text (`setLang` in `app.ts`).
- **Subtitles** (`subtitles.ts` pure, `subtitle-dom.ts`, `format.ts`, `css/subtitles.css`): a text `parseSrt` reads is SubRip (`formatOf`: before Markdown), shown in Preview as a `<table>` of cues whose rows carry `data-line`; code that looks for `data-line` goes through `lineElements` / `lineElementOf` (`dom.ts`), not `view.children`. Only the cues' text is sent, numbered 1..n (`toWire`), always to the chat model, with `SUBTITLE_CONSTRAINT` as the first hard constraint (without it the model renumbered English cues by sentence) and genre 字幕 unless one is entered. `state.translation` is always SubRip: `translateSubtitles` rebuilds it from what the model wrote on every delta, keeping each cue's index and timing as the source wrote them; an empty or skipped number joins the cue before, a number out of order or past n is dropped; numbers missing at the end join the last cue when the run finished with `stop`, and are untranslated otherwise. `subtitleAlignment` finds the groups again from the two SubRip texts alone (click-to-sync, after Stop, on restore); no paragraph check, `POST /align` or link check.
  - **Chunks**: long runs loop and drift in one request, so `planChunks` cuts the cues into requests of at most `CHUNK_LIMITS` (cues, letters), each numbered 1..n again (`chunkText`), the next starting `overlap` cues before the previous one ends; the page sends them one after another (`streamSubtitles`, `Run.nextJob`), and a chunk that does not finish with `stop` ends the run. `translateSubtitles` joins chunk outputs in their overlap (`cutAt`). Reading aloud reads cue by cue (`cueBlocks`).
  - **Speakers**: when every cue with text starts with `label:` (or `label：`), and either all labels are ids `S\d+` or there are at most 12 and one repeats (`speakerColumn`), the table has a Speaker column (`cue-meta`: neither hover nor reading aloud sees it). Only ids are taken off in `toWire` and put back by `translateSubtitles` (`withSpeakers`); a name label stays in the text for the model to translate.
- **Paragraph matching** (`paragraphs.ts` pure, `matchBlocks` in `app.ts`): an `Alignment` is both texts' block starts and `groups` of consecutive blocks that translate each other (an empty side: no counterpart); consumers go through `counterpart(a, side, line)`, never block indexes. After a translation that finished with `stop`, equal block counts give block i ↔ i; otherwise, when `/health` `align` is available, both sides have at most 256 blocks and the source has at least `MIN_MATCHED_BLOCKS` = 8, the page asks `POST /align` with `unit: "paragraphs"`. A late answer is dropped. Blocks are `blockStarts`'s (blank-line paragraphs or lines, a fenced code block being one), not the Markdown parser's, which would hide a dropped list item. On failure the plain note stays.
- **Sentence mark** (`sentence-hover.ts`, `sentence-spans.ts` pure so bun test needs no DOM, `text-groups.ts`, `css/sentence.css`): the sentence under the pointer is a `Range` painted by the CSS Custom Highlight API (`::highlight(sentence)`; no element is added to the tree;). Sentence ends are the SaT boundaries cut at 0.5, else `Intl.Segmenter`. Off while a translation runs, and where `Highlight` or `caretPositionFromPoint` is missing (`scripts/lint_es.ts` `settings.polyfills`; remove when widely available). `prefetchSentences` (`app.ts`) asks once a translation is finished.
- **Sentence counterparts** (`sentence-align.ts`): while `syncActive()`, hovering a sentence also marks its `POST /align` group in both views once SaT has answered for every group; until then, or on failure (10 s backoff), the mark is the sentence alone.
- **History** (`history.ts`): `localStorage` only; the server must never learn of it. An entry's optional `blocks` is `"same"` or the `groups` `POST /align` found; `restoredAlignment` revalidates it against both texts. The link check is not restored; subtitles keep no `blocks`.
- **Resuming** (`resume.ts`): iOS cuts the SSE connection when the page leaves the screen, so the page always asks for `resumable: true`, reconnects after the last event id seen, and Stop also sends `DELETE`. A page that is unloaded for good (`pagehide` with `persisted` false: closed, reloaded, left) cancels its job the same way (`Run.cancel`, `keepalive`): no page can pick it up again, and its notification would lead nowhere. A page only hidden or suspended keeps it; one the OS kills in the background gets no event, so its job runs on.
- **Service worker** (`sw.ts`, `pwa.ts`): never serves a stale file. Caches nothing on loopback (push still works there). Elsewhere it fetches `/asset-manifest.json` (path → ETag of every file in `public/`, built by `static.ts`, rebuilt after a change seen by `public-watch.ts`, which dev reload also uses) and serves a cached file only when its stored `ETag` equals the listed one, else downloads and caches it. The bulk prefetch is switched off (`if (false)` in `prefetch`: it only sped up the second visit, at 12 MB on the first). `/api/`, `/__dev/`, unlisted paths and range requests go to the network.
- **Notifications** (`public/push.ts`, `sw.ts`): while `/health` `push` is available, the Translate submit and the Transcribe dialog button call `askForNotifications` synchronously (a permission prompt needs the gesture); every accepted job is then subscribed (`notifyWhenDone`, after the prompt is answered), resubscribing when the server's key changed. The worker's `push` always shows a notification (Chrome penalizes silent pushes); a click focuses the page or opens `/`. A page that was discarded meanwhile does not know the job.
- **Reading aloud** (`speech-text.ts` pure, `speech-buffer.ts` audio, `speech.ts` player, `speech-ui.ts` page side): one side at a time. `speechSegments` builds utterances from `parseLines` for Markdown-shown text (never the raw text), cut into pieces of similar length (`LIMITS` per language) by a Viterbi DP as wtpsplit's `constrained_segmentation`; never inside a word (outside zh/ja) or a surrogate pair. Sentence ends are SaT's probabilities from `POST /segment`; one `SentenceBoundaries` in `app.ts` serves reading aloud and the sentence mark, and is aborted by a new translation or Clear, not by Stop. `speech-text.ts` derives the shown text from the AST and carries offsets through `clean`'s edits; `speechTexts` lists exactly the strings `speechSegments` looks up by (`test/speech-boundaries.test.ts` pins the mapping). A pick waits at most `SEGMENT_WAIT_MS`; failure or timeout cuts by `Intl.Segmenter` alone. One `AudioContext` created in the click; pause is `suspend()`. A new translation, Clear, switching the source to Raw or changing From stops the reading.
  - **Read-from gutter** (`read-gutter.ts`): Read aloud is an `aria-pressed` toggle that starts nothing: it shows a column of "Read from: …" buttons, one per spoken block; released, it hides the column and stops. Targets are ≥ 24 px (2.5.8), not 44: one-line blocks are shorter.
- **Opus stream** (`public/opus.ts`, `src/opus-stream.ts`, `src/opus-ffi.ts`): the page probes once whether `OfflineAudioContext.decodeAudioData` decodes an embedded Ogg Opus file (not `canPlayType`) and, if so, sends `Accept: audio/ogg, audio/wav;q=0.5`, otherwise no `Accept` (WAV). The server resamples with libsoxr, encodes with libopus (CELT only, complexity 6; one encoder per response, freed when the stream ends or is cancelled) and muxes with `public/ogg-opus.ts`. `opus_encoder_ctl` is variadic: bound twice with fixed signatures, which holds on x86-64 and Linux aarch64. `opusLoader` answers undefined when `vendor/opus` is missing, so WAV is sent. Changing the libopus pin: recheck the `OPUS_*` numbers in `opus-ffi.ts` against `opus_defines.h`, and that packets are still CELT (TOC config 27).
- **Uploading audio** (`audio-upload.ts`; its `OggOpusEncoder` also encodes re-encoded recordings): Web Audio mixes down and resamples (WebCodecs does neither), then `encodeUpload` sends Ogg Opus when the server lists `audio/ogg` in `upload_types` and `AudioEncoder.isConfigSupported` says yes, else WAV (also when an encoder fails after saying yes).
- **Opening files and PDF** (`open-file.ts`, `open-ui.ts`, `pdf.ts`, `pdf-worker.ts`): browser-only like history; the server only serves the bundled libraries (offline by design, CSP `default-src 'self'`; `pdfInstalled()` hides PDF when missing). Text enters through `loadSource(text, preview)`, which Clear also uses. A later pick wins, and a result arriving after a translation started is dropped. An image is drawn on a `<canvas role="img">` (the CSP allows no `blob:` or `data:` picture; `media-src 'self' blob:` is the one exception, for the player) and sent to the chat model whatever the model choice; no Markdown, sync or history entry for it.
  - e2e pins Playwright `~1.64.0`: older Chromium ran out of memory compiling pdf-inspector's WebAssembly on a large PDF. Bump deliberately.
  - pdf-inspector limits: CJK in non-embedded fonts naming a predefined CMap comes out as U+FFFD (page 3 of `sample.pdf`, used by `e2e/open.spec.ts`); two-column pages may be misordered; password-protected files are refused.
- **Transcribing a recording** (`transcribe-flow.ts`, `media-file.ts`, `matroska.ts`, `transcription.ts` pure; `transcode.ts` + `pcm.ts` for re-encoding): `open-file.ts` kind `media` (`.wav .ogg .oga .opus .webm .mkv .mka`, offered while `/health` `transcribe` is available). What the server takes is never re-encoded: WAV and Ogg Opus go as they are or cut at `max_seconds`; an Opus track of WebM/MKV is remuxed into Ogg by `OggOpusMuxer`. Ogg carries no times, so a late start up to `LEAD_LIMIT_SECONDS` and gaps of ≥ 10 ms are filled with 20 ms CELT silence packets (`F8 FF FE`, stereo `FC FF FE`); a later start sets `Recording.offset`, added to every cue time. Only frame 0 of a block is compared (mkvmerge laces Opus without frame durations); a chained segment ends the recording. The transcription is a `Run` (`jobId`, `cancelUrl`, as a resumable translation): every segment rewrites the whole SubRip (`transcriptSrt`, labels `S01:`) into a growing `createOutput` on the source view; Stop or a failure keeps what was written. Stop (`Run.onStopping`) sends the `DELETE` but reads on until the job's `cancelled` (the worker cannot stop inside CED, a separation, VAD, the model load or MOSS's prefill); a second Stop aborts the stream.
  - **Re-encoding** (`transcode.ts`): everything else decodable (AAC, Vorbis, FLAC, MP3, PCM, Opus of 3–8 channels, WAV the server would not take whole, all Opus when `upload_types` lacks `audio/ogg`) goes through WebCodecs `AudioDecoder` (`probeMedia` asks `isConfigSupported` per track; an undecodable track is a disabled radio). Output: Ogg Opus by a streaming `OggOpusEncoder` where the server takes Ogg, else a mono 44.1 kHz 16-bit WAV capped at `max_bytes`. `PcmTimeline` places chunks by timestamp (before 0 dropped, gaps ≥ 10 ms filled). Chromium's decoder timestamps ignore jumps until `flush()`, so `decode` flushes first at real gaps (`matroskaChunks`, `GAP_US`). Waits on a full codec queue take its `dequeue` event; without `ondequeue` yield through a `MessageChannel`, never `setTimeout(0)` (4 ms clamp) or a microtask (lets no codec callback run). Compressed (`ContentEncoding`) and encrypted tracks stay refused; MP4/MOV is unsupported.
  - **Player** (`media-ui.ts`, `media-player.ts` pure): from `begin` until another `loadSource` or a history restore, `#source-media` above the box plays the file from a `blob:` URL (no copy). Chromium plays the first audio track it decodes, so `playbackOf` hides the other audio tracks in place (TrackType becomes `0x20`, the CRC-32 elements over Tracks and TrackEntries become Void). A track `canPlayType` refuses or that cannot be hidden goes to the `Recording` sent, audio only, its times minus `offset`; the file's `error`, or no `loadedmetadata` in 10 s, falls back the same way. The cue at the playhead (`cueAt`) is `cue-playing` + `aria-current="time"` in the source and, through `sync.active()` and `counterpart`, in the translation. A `ReadGutter` with verb "Play from" sits in the source scroller; the Read aloud gutter takes its place while open. The player watches the source view (`MutationObserver`: rows are rebuilt on the next frame). Playing stops reading aloud, a reading pauses the player.
  - **Captions** (`captions.ts` pure, `caption-tracks.ts`): a video with a picture gets `<track kind="subtitles">`s Original, Translation and Original and translation, rebuilt as either text changes. Each `src` is an empty WebVTT `blob:` and cues are added by script after its `load` (earlier ones are dropped); not `addTextTrack()` (tracks cannot be removed), not a `<track>` without `src`, never `disabled` (it would not load). A track or Off the reader picked is kept.
  - **Cue timing** (`cue-timing.ts` pure; the dialog's "Time the cues for reading", on by default): MOSS ends a segment later than fansub timers do, so only the start moves (`LEAD` 75 ms); starts and ends snap onto video keyframes (`demux` `keyframes`, less forced or fixed-GOP ones, `FORCED_RUNS`) within small windows, and cues under 0.15 s apart meet on a cut, else halfway. WAV and Ogg have no cuts.
- **Word documents** (`docx.ts`, `docx-worker.ts`): `.docx` only, read by undoc (the `undoc` orphan branch of this repository; build command in its README). Rebuilding: commit the output on that branch, then update `UNDOC_COMMIT` and the checksums in `fetch_web_libs.ts`, and the notices if the crate list changed.

### Engine and packaging

- Changing the audio.cpp pin (`build_audiocpp.ts`) or the speech GGUF: check `src/audiocpp-ffi.ts` signatures and struct layouts against the new `audiocpp.h` by hand; the library still exports only `audiocpp_*`; both patches still apply and upstream added no abort or `custom_schema_output` accessor. For transcription: MOSS still streams (`asr`, mode `streaming`), its output format still matches `SEGMENT` in `transcript.ts`, its budget error still says "reached max_tokens", and Silero's weights are still `assets/framework/models/silero_vad/silero_vad_16k.safetensors`. RoFormer still reads the session option `mel_band_roformer.num_overlap` (`src/models/roformer/session.cpp`; options are not validated, so a renamed one would only slow separation down unnoticed).
- Changing the llama.cpp pin (`build_llama.ts`): check `src/llama-ffi.ts` against the new `llama.h` and `mtmd.h` and the CMake options by hand; libmtmd's API is unstable, so read what the shim calls, check that it still exports `stbi_load_from_memory` and that `engineSize` (`src/image.ts`) still equals `calc_size_preserved_ratio`; translate an opaque, a transparent and a full-size image; rerun the long-document check. MTP uses `src/llama-ext.h` ("breaking changes allowed"): check the functions `llama-shim-ext.cpp` wraps, the `llama_batch_ext` / `llama_process` / `n_rs_seq` / `ctx_type` calls in the shim and the draft-mtp driver in `common/speculative.cpp`; rerun the MTP speed and teacher-forced checks. After editing `llama-shim.c` or `llama-shim-ext.cpp`: `bun scripts/build_llama.ts --shim`, and declare new functions in `llama-ffi.ts`.
- Changing the ONNX Runtime pin (`VERSION` and checksums in `fetch_onnxruntime.ts`): its C API is an append-only struct of function pointers; recheck every index in `SLOT` (`src/onnxruntime-ffi.ts`) and `ORT_API_VERSION` against `onnxruntime_c_api.h` (a wrong slot calls another function, with no error), run `test/sat-native.test.ts` and `test/labse-native.test.ts` with the models installed, and check the Windows DLL's imports. Open the library by full path.
- `packaging/bunfig.toml` is Bun's config for both packages (`env = false`, `telemetry = false`); new Bun flags go there, except `--disallow-code-generation-from-strings=strict`, which bunfig cannot express and which `AppRun`, `launcher.c` and the installer's smoke test pass explicitly.
- Builds that leave this machine (AppImage) must not be `--native`. `package.json` has no `check`, `lint` or `format` script on purpose: each would shadow the builtin.
- AppImage (`build_appimage.ts`, `packaging/appimage/`): a new top-level directory or file the server reads is added once, in `stageApp` (`scripts/stage_app.ts`, shared with `build_installer.ts`, which also holds `requireAllVendored`: a new fetched library goes there); only `src/*.ts` is copied, so `src/page/` is named, and `scripts/fetch_models.ts` is packed with what it imports of `scripts/` (`fetch_tools.ts`, free of project imports). `AppRun` deliberately leaves `LD_LIBRARY_PATH` unset (the browser is started from this process). A new `APPIMAGETOOL` or `RUNTIME` needs a new URL and checksum; the runtime stays static.
- Third-party notices: `THIRD_PARTY_NOTICES.md`. `fetch` (`acceptNotices` in `fetch_models.ts`) prints `NOTICES[id]` and needs "yes" on stdin; there is deliberately no bypass flag. A new pin, library or model means checking its license and updating the markdown, `NOTICES` and `AppRun`; a test keeps them in step.
